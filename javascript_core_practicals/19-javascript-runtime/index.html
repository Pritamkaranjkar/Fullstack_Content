Topic 19 of 21

JavaScript Runtime

The call stack, Web APIs, callback queue and microtask queue — how single-threaded JS handles async work.

NOTES.md

The pieces

  • Call stack — where synchronous function calls execute, one at a time
  • Web APIs — browser-provided features (timers, fetch, DOM events) that run outside JS
  • Callback / macrotask queue — holds setTimeout, DOM event callbacks
  • Microtask queue — holds resolved Promise callbacks; runs before the next macrotask
  • Event loop — keeps checking: "is the stack empty? run the next queued task"

Why this ordering happens

console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// Output: 1, 4, 3, 2 — sync first, then microtasks, then macrotasks

JavaScript is single-threaded: it can only ever do one thing at a time on the call stack. Everything async is scheduled elsewhere and only re-enters JS once the stack is clear.
